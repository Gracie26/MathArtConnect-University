# Architecture

MathArt Connect is an Expo (SDK 58) app written in TypeScript. It uses Expo Router for navigation and Supabase for auth and data. Native folders (`ios/`, `android/`) are generated by Continuous Native Generation and are never edited by hand.

## Theming

- `theme/tokens/palette.ts` is the only file that contains raw hex values. Brand: Deep Teal primary, Modern Blue secondary, Warm Coral accent, Amber achievement, Emerald success, Red error, Soft Sand / Charcoal neutrals. No purple, violet or indigo.
- `theme/tokens/colors.ts` maps the palette to semantic roles (`background`, `surface`, `textPrimary`, `primary`, `tabActive`, ...) for light, dark and high-contrast variants.
- `theme/tokens/typography.ts` (Inter for text, JetBrains Mono for mathematics) and `layout.ts` (spacing, radius, shadows, touch targets, max content width).
- `ThemeProvider` resolves `system | light | dark` plus high contrast. Light is the default; learners change it in Settings › Appearance. Components read it through `useAppTheme()`.
- Display preferences (theme, high contrast, Reduce Motion, ambient art) live in one store, `features/preferences/displayPreferences.ts`. It saves them on the device (AsyncStorage; `localStorage` on web, read synchronously so the first frame has the right theme). The root layout waits for them before drawing, and `public/index.html` paints the saved light/dark background before the JavaScript loads, so there is no flash. For signed-in learners, `usePreferenceSync` also keeps theme, high contrast and Reduce Motion in `user_preferences` (`services/preferences/`). The more recent choice wins, by device `changedAt` against the row's `updated_at`, and an account row still at its defaults never overrides the device. Ambient art has no account column and stays per device.
- Dark mode has its own role values (deeper teal hero, brighter teal/blue/coral/amber accents), not an inversion of light mode.
- Decorative art is generated from real functions in `lib/art/curves.ts` (cubic with tangent, Lissajous, rose curves), never stock images.
- `__tests__/theme.contrast.test.ts` checks the colour roles against WCAG AA.

## Content model

Topics are configurable content. Screens must never hard-code a topic.

- `content/types.ts` defines `TopicDefinition` → units (subtopics) → lesson steps. Every subtopic uses the same 10-step lesson: Concept, See it, Explore, Try it, Worked example, Practise, Play, Create, Reflect, Review. Steps hold typed `ContentBlock`s:

- paragraph, maths, definition, callout and key-points summary
- theorem (with an expandable proof), formula, formula list and two-column table
- expandable derivation
- worked example (method, step-by-step reveal, optional "Why this step?")
- practice group: a list of `PracticeItem`s

A step is either `available`, or `planned` for a later phase. Planned steps can be viewed but never count as done. A step may hold many cards; material is split into cards rather than long text blocks.

- **Study time is calculated, never typed in** (`content/estimate.ts`). A subtopic's estimate is the time to work through it:
  - reading at 120 words a minute, plus a quarter of a minute per displayed formula;
  - 1–3 minutes per worked example, by number of steps;
  - 2, 3 or 4 minutes per question, by difficulty;
  - a quarter of a minute per quick-check question;
  - one practice set in Practise (two questions per method, at most eight), not the whole tutorial bank;
  - one go at each Explore tool (3 min), game (4 min) and Create activity (6 min);
  - Reflect (1.5 min) and Review (2 min).

  A topic is the sum of its subtopics. Displays round to the minute under 10 minutes and to 5 minutes above that, as in "About 1 hr 20 min". Time left counts the steps not yet completed. `learning_units.estimated_minutes` in the migrations is informational only.

- `content/registry.ts` lists the bundled topics: **Integration** (`content/topics/integration/`, 7 subtopics; the active topic) and **Integration as a Process of Finding the Area Under the Graph** (`content/topics/area/`, 8 subtopics). `demo-calculus-focus` is kept as infrastructure, marked `isDemo`, and never listed to learners (`listLearnerTopics()`).
- `content/activeTopic.ts` picks the active topic in this order: `EXPO_PUBLIC_ACTIVE_TOPIC_ID`, then the database's active topic, then the bundled default.

To add a topic, create `content/topics/<id>/index.ts`, register it, and add an insert-only migration for its `learning_topics` / `learning_units` rows.

### Source traceability and solution visibility

- Integration content covers the complete readable UNAM S3512MC Chapter 1 notes and Tutorial 1. `inventory.ts` lists all 115 Chapter 1 items, including 36 worked examples and 13 "You Try It" items and exercises. Every block links to its item through `source.inventoryId`. `sources.ts` maps every section and all 84 Tutorial 1 parts to a subtopic. The PDFs are **not** bundled; see `docs/source-material/README.md`.
- Practice data:
  - `chapterPractice.ts` holds the chapter "You Try It" items and exercises, shown in Try it.
  - `appPractice.ts` holds the Try it steps of Understanding Integration (§1.1–1.2) and Basic Integration Rules (§1.3–1.4), whose sections have no "You Try It" items. Each has two parts, always labelled **App practice** and never presented as UNAM questions:
    - a quick check (`quickCheck` block, `components/learning/QuickCheck.tsx`): choose an answer, get feedback on that choice, try again, ask for a hint (app guidance); the answer is never revealed first;
    - My Working questions (checked by differentiation in `integration-solutions.test.ts`). They are in `retrievalItems`, so course question counts are unchanged.

    Both steps stay optional, as before, so existing progress is unchanged.

  - `tutorial1.ts` holds all 84 tutorial parts, shown in Practise and grouped by technique.
  - `practice.ts` is the shared builder and filters. Each `PracticeItem` stores its technique, difficulty, recommended practice mode, review flags and an app-authored solution.
- `npm run audit:content` fails if any inventoried item or tutorial part has no mapped content. It also checks every stored anti-derivative by numerical differentiation, using the test-only evaluator in `test-utils/texEval.ts`.
- The notes' section structure (1.1 to 1.14 and Table 1.1) is learner-visible, each section openable inside its subtopic. Tutorial and exercise numbers stay internal; questions are labelled "Try it", "Exercise", "Practice", "Guided Practice", "Independent Practice" and "Challenge".
- Hints and walkthroughs for questions not withheld for review are shown as "App guidance", never as official UNAM or lecturer solutions.
- `manualReview.ts` is the manual-review register (MR-01 to MR-16). Source ambiguities are recorded there and never silently corrected:
  - Lesson material under review is shown exactly as printed, with an "awaiting lecturer review" note.
  - Practice items blocked by a review item are withheld from learners. Reviewer mode shows them.
- Every solution has a `SolutionStatus`. Learners see only `unamSource` (printed in the notes) and `lecturerApproved`. App-authored solutions are `pendingLecturerReview` and stay hidden. They appear only in development builds with `EXPO_PUBLIC_REVIEWER_MODE=true` (`content/visibility.ts`).

### Topic 2: Integration as a Process of Finding the Area Under the Graph

`content/topics/area/` covers the Chapter 2 notes (printed pages 23–42) and the 69 Tutorial 2 parts that belong to it, following the approved source audit:

- **Subtopics.** There are 8: Area Under a Graph and Riemann Sums (§2.1, §2.2), The Definite Integral (§2.2.1, including the Mid-point Rule), Properties (§2.2.2), the FTC (§2.3), the Mean Value Theorem for Integrals (§2.4), Improper Integrals: Infinite Intervals (§2.5, §2.5.1), Discontinuous Integrands (§2.5.2) and the Comparison Test (§2.5.3). The ten printed headings are openable section pages (`/topic/integration-area/section/2-5-1`).
- **Inventory.** `inventory.ts` lists all 112 source items, including 11 worked examples and 17 figures. `manualReview.ts` holds MR2-01 to MR2-08 (shown as printed with a note), MR2-T1 (Tutorial Q3, `dt`) and MR2-T2 (Q8(d), ln x on [0, 1]); the last two are withheld from learners. MR2-SOL covers the app-authored solutions.
- **Figures.** Figures are data (`lib/figures/scene.ts`) drawn by `components/figures/MathFigure.tsx` with react-native-svg at any width, in theme colours. `figures.ts` recreates Figures 2.1–2.16 and the unnumbered pair in §2.1. App illustrations (left endpoints, midpoints, example drawings) are always labelled "Illustration made for the app". A content block `{ type: 'figure' }` shows a figure; a worked example may carry `figure` so the drawing stays with the calculation.
- **TeX.** The TeX subset now includes `\sum` and `\lim` (limits stacked), `\bar`, `\underbrace{…}_{…}` and the ignored `\big`/`\Big` sizes.
- **Definite-integral checking.** Practice items with a `definite` spec (integrand or pieces, limits, singular points, expected answer) are checked by `lib/math/definite.ts`. My Working accepts:
  - Δx and xᵢ definitions;
  - Riemann sums in n and ith terms in i and n, compared with Rₙ, Lₙ and Mₙ;
  - anti-derivatives, passed to the Topic 1 checker;
  - partial integrals A(t) for improper integrals;
  - `lim …` lines and inequalities for the Comparison Test;
  - final answers that are values, rounded approximations, "diverges", converges/diverges verdicts, or Riemann-sum terms.

  A written comment (Q11(c)) is never graded: `components/practice/WrittenResponse.tsx` shows a text box, saves the response through `record_activity` (activity type `practice`, metadata `kind: 'writtenResponse'`), loads the latest saved response when the question is reopened, and offers the app guidance after saving.

- **Practice.** The practice screen filters by source (`?source=chapter|tutorial`, labelled "Chapter practice" and "Tutorial 2 practice" from `TopicDefinition.practiceSources`) and by method (`?method=`).
- **Tutorial 2 Question 1(a)–(g)** practises Chapter 1 methods and lives in Topic 1 (`content/topics/integration/tutorial2.ts`): (a) under Integration by Parts (§1.10), (b)–(g) under Advanced Integration Patterns (§1.12). "Show that" reduction formulas are checked with `check.answerMayContainIntegral`.
- **Explore.** There are nine tools in `components/explore/area/` (pure maths in `lib/explore/area.ts`): the Riemann Sum Explorer (right / left / sample / midpoint), From Sums to the Integral, the Mid-point Rule Lab, Properties as Areas, Area Accumulation (SFTC), the Mean Value Rectangle, Area to Infinity, Area Next to an Asymptote and the Comparison Lab.
- **Play (Phase D1).** Eight games in `content/topics/area/games.ts`, one per subtopic: Riemann Builder, Sum to Integral, Property Builder, Area–Derivative Link, Equal-Area Height (labelled App practice, since §2.4 has no exercise), Converge or Diverge, Approach the Asymptote, and Compare & Decide.
  - They run in the shared `GameShell` through a `widget` round kind (`lib/games/engine.ts`). The graph widgets live in `components/games/area/` and their pure evaluations in `lib/games/areaWidgets.ts`.
  - Every scored action is a mathematical decision, and feedback explains why. Fixed tapping cannot win: prediction answers vary, tolerance rounds cap n, and "nothing follows" in Compare & Decide is acknowledged (`cannotCheck`) but does not finish the round.
  - GameShell provides `ScrollLockContext`, so sliders in rounds keep the page still.
- **Create (Phase D2).** Two studios share `components/art/area/AreaArtStudio.tsx` and `AreaArtCanvas.tsx`; the model, geometry, templates and "Math behind my art" are in `lib/art/areaArt.ts`.
  - The **Riemann Mosaic Studio** has the templates Staircase Wave, Area Skyline, Midpoint Mosaic, Layered Riemann Landscape and Integral City.
  - The **Accumulation Art Studio** has Accumulation Flow, Mean Value Bands, Convergence Trail, Asymptote Trail and Twin Comparison Trails.
  - Layer kinds are `mosaic` (left / right / midpoint / mean value bands), `accumulation` (f and A(x) as linked layers, moving x, constant multiple k, repeated accumulation curves) and `trail` (A(t) for improper integrals).
  - The canvas comes first. Course-aligned controls (teal band, "■ COURSE-ALIGNED") are visually separate from the collapsible creative-extension controls (coral band, "✦ CREATIVE EXTENSION": mirror, repeat, spacing, gaps, line weight, opacity, colour, colour mode). Creative settings never change the mathematics.
  - Layers can be shown or hidden, duplicated, reordered and deleted. Zoom, pan, undo and redo use buttons.
  - Eight Create activities (`AREA_STUDIOS` in `activities.ts`, `TopicDefinition.areaStudios`) open a studio on a subtopic's template. Saved compositions have `kind: 'area'` and hold the full project.
- **Reflect and Review (Phase D3, D4).** `content/topics/area/review.ts` holds, per subtopic:
  - one mathematical reflection question;
  - a recap: key concepts, formulas, theorem conditions and common errors;
  - one or two **App practice** retrieval questions (`sourceType: 'app-practice'`, `TopicDefinition.retrievalItems`).

  Retrieval items stay out of `practiceItems`, so course counts are unchanged. `answerableItems(topic)` includes them wherever attempts are looked up (Review, My Work, Progress). `features/review/buildReview.ts` `nextAction` picks one next step from real history only.

- **Evidence.** `content/topics/area/evidence.ts` and `docs/topic2-phase-d-evidence.md` record the research behind each Play and Create design. This is internal only and never shown to learners.
- **Database.** `supabase/migrations/20261014000000_integration_area_topic.sql` is insert-only. It adds the topic and its 8 units, because progress rows reference them by foreign key. It leaves Integration as the active topic.
- **Tests.** `__tests__/area-content.test.ts` is the source-completeness audit. `area-solutions.test.ts` checks every stored value numerically with independent quadrature. `area-screens.test.tsx` opens every section, lesson step, practice view and lab.

### Mathematics

- `lib/math/tex/` is a native, WebView-free renderer for a LaTeX subset: a parser to a layout tree, a spoken form for screen readers, and `$…$` inline maths in text. Unsupported commands throw `TexParseError` and are not guessed. `components/math/MathExpression.tsx` and `MathText.tsx` render it with theme colours.
- `lib/math/tex/evaluate.ts` evaluates content TeX numerically. Practice uses it for each question's integrand; tests use it to verify stored answers.
- Answer checking lives in `lib/math`, separate from the UI. It never uses `eval` or `new Function`, and only an allow-list of symbols and functions is recognised.
  - `input/parse.ts` reads learner input (plain text such as `(3x+5)^6/18 + C`, `∫ u^5 du`, `u = 3x+5`).
  - `input/toTex.ts` prints the live preview.
  - `input/evaluate.ts` computes values and exact derivatives with dual numbers. A learner-written integral counts by its integrand; a substituted variable is evaluated through its definition.
  - `check.ts` checks each step: a rewrite of the integrand, a form equal to the integral, an anti-derivative, a substitution definition, a differential (`du = 3 dx`) or an equation. It also checks final answers, noting a missing `+ C`.
  - Whatever cannot be checked reliably (unreadable input, unknown symbols, inverse substitutions such as `x = 2 sin θ`) returns "cannot check" with an explanation, never "incorrect".
  - `validation.ts` exposes the same engine through the `AnswerValidator` interface (`numericValidator`).
  - Common formatting variations are accepted: a lower-case `+ c` or `+ k` as the constant of integration (only as a term on its own, and only when that letter is not the question's variable, a question constant or a substitution), and capitalised function names such as `Sin x` (not `Ln`, which can mean Lₙ).
  - Numeric answers given as rounded decimals are accepted to four decimal places (or four significant figures) in every topic: definite integrals (`definite.ts`), values of partial derivatives (`partial.ts`) and critical points (`applications.ts`), with a note that an exact form is better.
  - `docs/ANSWER_CHECKING.md` explains, for every checker, what is accepted and what is not.

### Progress

`features/learning/progress.ts` derives progress from saved `lesson_progress` rows only:

- A step counts once the learner continues past it.
- A subtopic is complete only when all its required steps are done, so a planned required step blocks completion. Concept, See it, Try it (where the notes have "You Try It" items), Worked example and Practise are required; Explore, Play, Create, Reflect and Review are available but optional.
- Topic progress is the share of required steps done.
- There is no mastery score in the app. Home and the topic page show **practice accuracy** instead: the share of checked My Working answers that were correct, shown only after at least 5 checked answers (`MIN_ANSWERS_FOR_ACCURACY` in `features/learning/studyDay.ts`). `estimateMastery` in `progress.ts` is kept as a tested helper but is not shown.

Routes:

- `app/(app)/topic/[topicId]/section/[sectionId].tsx`: one section of the course notes, e.g. `/topic/integration/section/1-6-1`. Built from `topic.sections` (`content/topics/integration/sections.ts`); reached from the lesson's "In the course notes" chips.
- `app/(app)/topic/[topicId]/practice.tsx`: the Guided, Independent and Challenge modes, with a `mode` and optional `unit`, `source` (`chapter` / `tutorial`) and `method` parameters.
- `app/(app)/practice.tsx`: the Practice hub (Home > Practice). For every learner topic: chapter practice and tutorial practice with real question counts, the three practice modes, and practice by subtopic. Questions withheld for review are not counted.
- Every practice question has "My working" (`components/practice/MyWorking.tsx`).

Learn shows the topic in focus (the first started and unfinished one) as a full card with the one primary action; the other topics are compact rows. Explore (the Visual Calculus Lab) shows one topic at a time through a topic switcher, with compact tool rows grouped by subtopic.

The topic page puts the simplest thing first:

1. Progress, time left and one Continue button (`TopicProgressSummary`).
2. The subtopics as a guided path (`components/learning/LearningPath.tsx`). Completed subtopics are one row, the current one is open (summary, time left, and "jump in" chips for Learn, Worked examples, Try it and practise, Explore and create, Review), and later ones stay folded until tapped. Only one is open at a time.
3. Practice modes, folded away in a collapsible section.
4. The activity groups.

`app/(app)/topic/[topicId].tsx` (topic landing; deliberately not `[topicId]/index.tsx`, because Expo's typed-routes watcher mistypes nested index routes on Windows) and `app/(app)/topic/[topicId]/[subtopicId].tsx` (lesson shell; `?step=<key>` opens a step, otherwise it resumes at the next unfinished one).

## Interactive activities (Explore, Play, Create, Reflect, Review)

Activities are content: `content/topics/<topic>/activities.ts` lists each one with its subtopic, kind (`lab`, `game`, `studio`), source sections and, for Create, a `createType` (`graphArt`, `areaArt`, `structure` or `flow`). A lesson's Explore, Play and Create steps hold an `activities` block, so each activity sits under the subtopic that teaches it. The Explore and Create tabs list the same activities from the registry (`ActivityCatalog`).

- Route: `app/(app)/topic/[topicId]/activity/[activityId].tsx` (`?project=<id>` reopens saved Create work). `components/activities/ActivityHost.tsx` maps each id to its module through a deferred `require()`, so graph and art modules are only evaluated when an activity is first opened. It deliberately does not use `import()` with `React.lazy`: on web, Metro's development async chunks and the lazy retry did not reliably commit (activities stayed on the loading skeleton), and the same development runtime is used in Expo Go and development builds. The trade-off is that web bundles are not split per activity.
- **Explore**: one component per tool in `components/explore/`, sharing `ExploreScaffold` (links to the source sections; records an `explore` activity once the tool has been genuinely used). Every lab shows "How to use this lab" (goal, what to do, what to look for) from `content/labGuides.ts`; `__tests__/lab-guides.test.ts` fails if a learner-visible lab has none. Tool content is in `content/topics/integration/explore.ts`; testable logic (parity strategy, product-to-sum, reduction chains, the §1.14 structure, partial-fraction templates) is in `lib/explore/`.
- **Play**: `lib/games/engine.ts` defines round kinds (select, order, match, stages, input), evaluation with explained feedback, scoring (10 first try, 5 after a retry, −3 with a hint, never below 2; mistakes never cost points) and XP (`max(5, score / 5)`). `GameShell` shows a tutorial before first play, then hints, feedback, score, progress and a completion screen. Game content is `content/topics/integration/games.ts`.
- **Create**: `CreateActivity` opens straight onto a starter artwork in either the **Equation Art Studio** (graph art: Antiderivative Curve Art, Function Curve Composer, Transformation Art, Equation Art Studio, Trig Pattern Studio, Dynamic Pattern Studio) or the **Flow Composer** (Decomposition Map and Solution Flow Builder: structure and flow, no decorative graph). "My saved projects" (collapsible) reopens, duplicates or deletes saved work. The Create tab shows each graph-art activity with its starter drawn live (`components/art/ArtPreview.tsx`).
  - Configuration lives on the topic (`TopicDefinition.studios` / `.flows`, from `content/topics/integration/create.ts`): functions allowed, starter artworks, questions, `equalScale` (equal units on both axes so circles and petals keep their shape), `stamp` (keep a copy of the moving curve at the current parameter values) and `transform` (substitution tools such as u = ax + b; the original becomes the dashed "before" curve).
  - Expression rewriting for stamping and transformations works on the parsed tree (`lib/graph/expression.ts`: print, substitute, freeze parameters), never on raw text.
  - Animate panel: the learner chooses the parameter (or all), speed (slow, normal, fast) and direction (increase, decrease, back and forth), then Play, Pause, Step or Reset (`advanceParameters`). With Reduce Motion on, Play is hidden and Step moves one step at a time. While animating, curves are sampled at half density.
  - Starters are labelled `course` or `extension` (`StudioPreset.category`); the gallery shows "Course-aligned" and "Creative extensions" separately, every studio opens on a course-aligned starter, and an extension shows a "Creative extension" label above the canvas and in "Math behind my art".
  - Polar layers have an optional `placement` (h, k, scale s, rotation φ): drawn at x = h + s·r(θ)cos(θ + φ), y = k + s·r(θ)sin(θ + φ). The equation r(θ) is unchanged and the placement is shown in "Math behind my art".
  - Graph axes are named (x, y) as well as numbered. "Math behind my art" includes "How to read this graph": what the axes mean, and for up to three visible layers the features computed from the equation (`lib/graph/features.ts`): the y-intercept (or that f(0) is undefined), where the curve meets the x-axis in view (jumps across asymptotes are not counted), symmetry, and the y-range in view; for polar layers the largest |r(θ)| and symmetry about the x-axis. Features are shown only where they exist.
  - `lib/graph/diagnose.ts` explains empty or odd canvases (all hidden, restriction hides everything, invalid interval, art off-screen, parameter at its limit, heavy composition, 30-layer limit) with fix-it buttons.
  - Phones: pan and pinch are batched to one update per frame; the page stops scrolling while a finger is on the canvas or a slider (`ScrollLockContext`, needed on Android); the canvas is at most 60% of the screen height; the layer editor is a keyboard-avoiding bottom sheet with Save and Cancel pinned above the keyboard.
  - Studio: layers (add, edit, rename, duplicate, reorder, show/hide, delete), cartesian and polar curves, domain and range restrictions, polar repeats and mirroring, parameters with min/max/step sliders, zoom, pan, pinch, reset, axes, grid, tap-to-trace, undo/redo (`lib/graph/project.ts`; slider moves are live but not added to the history), and "Math behind my art" (concept, equations, restrictions, parameters, transformations, questions, explanation). Expressions go through the learner maths parser and an allow-list of variables, parameters and functions (`lib/graph/sample.ts`); nothing is ever evaluated as code.
- **Reflect** (`features/reflect/ReflectCard.tsx`): one conceptual question, confidence 1 to 5, "what was difficult?" and an optional note, saved as a `reflection` activity. It is not a test, and confidence is never used for mastery.
- **Review** (`features/review/`): built only from the learner's own history (question attempts with retries and hints, game sessions, saved Create work, explore use, reflections). Actions: Retry, Review concept, Open worked example, Open Explore tool, Practise similar, Play again, Open saved Create work. With no history it says so.

Persistence (`services/repositories/learning/`, Supabase or the device-only dev backend): `question_attempts` (with `retry_of_id`, resolved by a later correct answer), `game_sessions` (events: per-unit retries and hints), `art_projects` (`composition`: the project plus readable equations, parameters, restrictions, canvas state and learner explanation), and `activity_history` written only through the `record_activity` RPC, which also adds XP (idempotent by id).

## Progress, Review My Work and Notifications

All three read the learner's real record through `features/insights/useLearnerRecord.ts`: lesson steps, question attempts, game sessions, art projects and the activity log. `loadLearnerRecord` loads one topic; `useLearnerRecords` loads several. Nothing is sampled or invented, and a failed load is shown as an error with Try again.

- Progress lists every learner topic.
- Review My Work has a topic switcher. `?topic=` chooses the topic, and so does a `?unit=` from that topic.
- Notifications come from every topic (`deriveAllNotifications`), with duplicate ids removed. There is a single inactivity reminder, which appears only when nothing has been recorded in any topic for 3 days.

- **Progress** (`app/(app)/(tabs)/progress.tsx`, `features/insights/progressReport.ts`): kinds of evidence are kept separate, with no single mastery number. The tab shows an overview (`features/insights/ProgressOverview.tsx`, model in `overviewModel.ts`): topics started, lesson steps done, practice checked and answers to review, up to three rule-based insights, and one card per topic. Each card opens the full report at `app/(app)/progress/[topicId].tsx`.
  - Completion: required lesson steps the learner worked through.
  - Practice: checked answers, giving accuracy, hints and retry improvement, by subtopic and by method.
  - Games: sessions, best and latest score, level and XP; "Not played yet" when never played.
  - Explore tools used, Create projects saved, and recent activity: active days over the last 14 days.
  - Confidence comes from Reflect ratings and is shown on its own.
  - Subtopic standing: "Needs attention" below 50% accuracy (at least 3 answers) or with 2+ open mistakes; "Strong" when the lesson is complete with at least 80% accuracy over 3+ answers; otherwise "On track", or "Not started".
  - Improvement: shown when a subtopic or method has 4+ answers and the later half is at least 10 points more accurate.
  - Recommendations: at most three, from simple rules (weak method, many hints, lesson done but practice weak, open mistakes, continue).
- **Review My Work** (`app/(app)/my-work.tsx`, `features/insights/workHistory.ts`):
  - one timeline of practice, games, Explore, Create, lessons and reflections;
  - per-question attempt history, with saved working, Retry inline and Open in the lesson;
  - "Needs review", grouping open mistakes by method. "Forgotten + C" is detected from the checker's outcome, which MY WORKING now saves with each attempt;
  - games history, saved creations (open, continue, duplicate, delete) and lesson history with Continue;
  - filters by type, subtopic and status (needs review, completed, last 7 days).
  - `?filter=review` opens the mistakes; `/mistakes` redirects there.
- **Notifications** (`app/(app)/notifications.tsx`, `features/notifications/`): an in-app centre only; no push notifications are sent.
  - Notifications are derived from the record by rules: unfinished lesson, inactivity after 3 days, questions to review, many hints → Explore tool, achievements, saved-but-unfinished work, and untried activities.
  - Ids are stable, so read and dismissed states persist until the facts change.
  - Read, dismissed and the three settings (learning, review, achievement) are stored on the device (AsyncStorage). No schema change was needed: the `user_preferences.notify_*` columns describe opt-in push reminders and are left for that future feature.
  - The Home bell's dot uses the real unread count.

## Services

- Screens never call supabase-js directly. They use `services/auth` and `services/repositories`.
- Every service call returns a `ServiceResult<T>` (`{ ok: true, data }` or `{ ok: false, error }`) instead of throwing.
- Learning-data failures are classified in `services/repositories/dataErrors.ts`: a network failure says the server could not be reached, an expired session (PostgREST PGRST301/302, HTTP 401) asks the learner to sign in again, and any other server error (for example a foreign-key violation because a topic's rows are missing) says the progress could not be saved, never that the connection was lost. Development builds log the real Supabase error (code, message, details, hint).
- `getSupabase()` returns `null` when the env vars are missing. Services then return `not_configured`. Learners never see backend wording; development builds (`__DEV__`) show a small "Dev · sample data" pill on Home instead.
- On native, sessions are stored encrypted (a SecureStore key plus AES in AsyncStorage). Web uses the supabase-js default.
- Learner writes carry client-generated UUIDs so that retries from the offline outbox (Phase 5) are idempotent.

## Home dashboard

`app/(app)/(tabs)/index.tsx` only composes; the sections live in `features/dashboard/components/`. Data flows `dashboardRepository.getDashboard(userId)` → `useDashboard()` (loading / ready / error) → `DashboardContent`. The repository builds the dashboard from real data: Continue Learning from lesson progress on the topic studied most recently, a rule-based next step (`nextAction`: open mistakes first, then practice for a started subtopic while fewer than 5 answers are checked, otherwise none), streak and XP from `profiles`, practice accuracy from `question_attempts`, mistakes to review from `v_mistakes_to_review`, and the last four lesson activities from `lesson_progress`. Failures are returned as errors, never replaced with sample data. `services/mock/mockDashboardData.ts` is for previews and tests only.

Layout: phones get one column in priority order (greeting with streak, XP and accuracy; Continue Learning; Next best step with weekly goals and badges; Recent activity). From 960 dp (desktop web) the dashboard is centred at max 1160 dp with a main column (Continue Learning, Next best step) and a side column (weekly goals, recent activity). There is no Quick Actions strip: Explore and Create are tabs, and the Practice hub and All games are linked from the bottom of the Learn tab. The tab bar stays bottom-anchored and centred.

## Authentication and account flow

`features/auth/AuthProvider.tsx` is the single source of auth state: `status` (loading / signedOut / signedIn), `user`, `profile`, `profileComplete`, `recoveryMode`, `onboardingComplete`, `signingIn`, `signingOut`, `error`. Screens call its actions (`signIn`, `signUp`, `signInWithProvider`, `saveProfile`, `signOut`, …) and never touch Supabase.

Routing is declarative. `app/_layout.tsx` wraps screens in `Stack.Protected` guards, so a state change moves the learner automatically:

| State                                 | Reachable                              |
| ------------------------------------- | -------------------------------------- |
| restoring session                     | startup screen (no sign-in flash)      |
| signed out, first launch              | onboarding                             |
| signed out                            | sign-in, sign-up, verify-email, forgot |
| password-reset link                   | reset-password only                    |
| signed in, profile setup not finished | profile-setup                          |
| signed in, profile complete           | the app (Home …)                       |

Backends (`services/auth/index.ts`): Supabase when configured; otherwise a **device-only development backend** in `__DEV__` builds, which is labelled on screen and has "simulate link" helpers in place of emails. A release build without Supabase reports accounts as unavailable.

Providers: email/password, Google (Supabase OAuth + PKCE through `expo-web-browser`), Apple (native sheet on iOS with a nonce, OAuth elsewhere). Google and Apple are off unless `EXPO_PUBLIC_AUTH_*_ENABLED=true` and Supabase is configured. Errors are mapped to friendly messages in `services/auth/errors.ts`, and an offline check runs before network calls.

Deep links: `mathartconnect://auth/callback` (or `/auth/callback` on web) handles verification, OAuth and `?flow=recovery` reset links. See docs/EXTERNAL_SETUP.md.

Privacy: the profile holds full name, programme, year and optional avatar only. The institution is never asked for: MathArt Connect is for University of Namibia students, so it is a fixed value (`APP_INSTITUTION` in `config/app.ts`) shown on the profile and filled in for profiles with none. A value an older profile already stored is kept, and the `profiles.institution` column stays for compatibility. Research participation is never part of sign-up.

## Streak and XP

Both live in `profiles` and change only inside the `record_activity` database function (SECURITY DEFINER). The app never writes them directly.

- **Study day:** a calendar day in `streak_timezone` from `app_config` (default Africa/Windhoek, UTC+2 with no daylight saving). `features/learning/studyDay.ts` uses the same day boundary on the device.
- **Streak:** when an activity is recorded, the streak stays the same if the learner was already active that study day, goes up by 1 if they were last active the day before, and otherwise starts again at 1. `last_active_date` is updated. The stored number only changes when the next activity arrives, so Home shows `effectiveStreak`: the stored streak if the learner was active today or yesterday, otherwise 0.
- **What counts as a study day:** Explore tools completed, games completed, Reflect answers, written responses, and (with 0 XP) a checked practice answer, a completed lesson step or a saved Create project. The last three record one `Study day` marker per kind, topic and day (`recordStudyDay`), which are not listed in My Work, Progress or Notifications.
- **XP:** a completed game gives `max(5, round(score / 5))`; an Explore tool +5; a Reflect answer +5; a written response +2 (once per question per day). Practice, lesson steps and Create give no XP. XP is clamped to 0–500 per activity.
- **No double awards:** `record_activity` ignores an activity id it already has (no second row, no second XP or streak change), so retries are safe. Explore uses a daily id (`dailyActivityId`), so repeating a tool on the same day gives XP once. A second Reflect answer on the same subtopic and day gives 0 XP, and a game gives XP for its first completed session each day (later sessions save the score with 0 XP and say so).
- **Device-only dev backend:** XP is the sum of recorded activity, and the streak is counted from the study days of recorded activity (`streakFromDays`).
